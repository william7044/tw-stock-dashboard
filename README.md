# 台股籌碼儀表板（免費版）

用證交所、櫃買中心、公開資訊觀測站與集保結算所的**免費公開資料**，每天收盤後自動更新一份台股儀表板。
不呼叫任何 AI API，不需要任何付費帳號或金鑰；排程跑在 GitHub Actions 的免費額度內。

儀表板是單一 HTML 檔（`docs/index.html`），資料都嵌在檔案裡，離線也能開。

## 儀表板內容

- **大盤概況**：加權指數、櫃買指數、上市三大法人買賣超（億元）、上市融資餘額、上漲／下跌家數（含創一年新高／新低家數），附近 40 日走勢。
- **選股清單**（可搜尋、依市場／產業／均量篩選、點欄位排序；欄位可切換「綜合／技術面／基本面／成交量分布」）：

  | 分組 | 快速篩選 | 條件 |
  |---|---|---|
  | 籌碼 | 外資連買 | 外資連續買超 ≥ 5 天、5 日均量 ≥ 500 張 |
  | 籌碼 | 投信連買 | 投信連續買超 ≥ 3 天、5 日均量 ≥ 300 張 |
  | 籌碼 | 投信認養 | 投信 5 日買超佔股本 ≥ 0.5% |
  | 籌碼 | 大戶加碼 | 千張大戶持股比例週增 ≥ 0.5 個百分點且股東人數減少 |
  | 籌碼 | 融資大增 | 5 日融資餘額增加 ≥ 10%（風險訊號） |
  | 籌碼 | 內部人申報 | 近 30 天有董監／大股東申報轉讓持股 |
  | 基本面 | 營收高成長 | 月營收年增 ≥ 50%、今年累計年增 ≥ 30%、單月營收 ≥ 1 億 |
  | 基本面 | 營收創新高 | 最新月營收為近 12 個月最高、單月 ≥ 1 億 |
  | 基本面 | 高殖利率 | 殖利率 ≥ 6%、本益比 0～12 倍 |
  | 基本面 | 本益比低檔 | 本益比落在自己過去一年（每月取樣）最低 10% 的位置 |
  | 技術面 | 創 52 週新高／新低 | 還原股價創一年新高（或新低）、5 日均量 ≥ 300 張 |
  | 技術面 | 多頭排列 | 股價 > 5 日 > 20 日 > 60 日均線 |
  | 技術面 | 相對強勢 | 近 60 日漲幅贏過 95% 以上的股票 |
  | 技術面 | 爆量上漲 | 成交量 ≥ 前 20 日均量 2 倍、≥ 500 張且收漲 |
  | 技術面 | MACD 黃金交叉 | 今天 DIF 由下往上穿過 DEA |
  | 技術面 | RSI 超賣 | 14 日 RSI ≤ 30 |
  | 成交量分布 | 量大權值股 | 市值前 150 大、20 日平均成交值 ≥ 3 億元 |
  | 成交量分布 | 區間整理 | 60 日高低差 ≤ 25%、60 日漲跌 ±10% 內，前 120 日價值區落在這個箱子裡，收盤在價值區內 |
  | 成交量分布 | 跌深反彈 | 距 120 日高點跌 ≥ 20%、已離 20 日低點 ≥ 5%，POC 與價值區還在上方（套牢區） |
  | 成交量分布 | 整理突破 | 最近 10 日內帶量突破箱頂與價值區上緣、上方套牢量 ≤ 15%，而且還沒出場 |

  門檻寫在 `templates/dashboard.html` 的 `PRESETS`，可以自己改（成交量分布的門檻在 `stock_agent/volume_profile.py`）。
  技術指標都用「還原股價」計算（以每日漲跌價差串接），除權息不會造成假的跌破或新低。

- **個股細節**（點任一列）：40 日收盤價、成交量分布與買賣點（B／S）、外資與投信每日買賣超圖、估值、月營收、融資券、
  集保大戶分布、內部人申報。
- **訊號回測**：每個快速篩選條件在過去一年出現後，持有 5／20／60 個交易日的平均報酬、中位數、上漲比例，
  以及和同期全部股票平均相比的超額報酬；成交量分布另外統計「照 B 進場、S 出場」的實際交易（說明見下方「訊號回測」）。
- 依台股習慣，**漲／買超為紅色、跌／賣超為綠色**，數字一律帶正負號（色覺辨識障礙也看得懂）。支援深色模式。

## 資料來源

| 資料 | 來源 | 更新頻率 |
|---|---|---|
| 每日行情、加權指數 | 證交所網站 `afterTrading/MI_INDEX`（備援：OpenAPI `STOCK_DAY_ALL`） | 每交易日 |
| 上櫃行情 | 櫃買中心網站 `afterTrading/otc`（備援：OpenAPI） | 每交易日 |
| 三大法人買賣超 | 證交所 `fund/T86`、`fund/BFI82U`；櫃買 `insti/dailyTrade`（備援：OpenAPI） | 每交易日 |
| 融資融券 | 證交所 `marginTrading/MI_MARGN`；櫃買 `margin/balance`（備援：OpenAPI） | 每交易日（約 21:30） |
| 本益比、殖利率、淨值比 | 證交所／櫃買 OpenAPI | 每交易日 |
| 月營收、公司基本資料、內部人持股轉讓事前申報 | 公開資訊觀測站資料（經由證交所／櫃買 OpenAPI） | 每月／每日 |
| 櫃買指數、上櫃法人金額 | 櫃買 OpenAPI | 每交易日 |
| 集保戶股權分散表 | 集保結算所開放資料 | 每週 |

> 為什麼不全用 OpenAPI？OpenAPI 只提供「最新一天」，沒辦法回補歷史，也沒辦法補抓排程漏跑的日子；
> 證交所 OpenAPI 也沒有個股的三大法人資料。所以每日資料改用同一個機構網站上「可指定日期」的 JSON，
> 網站端點失敗時再用 OpenAPI 補最新一天。

資料依「政府資料開放授權條款」使用。只收普通股（4 碼代號），不含 ETF、權證、特別股。

## 在自己電腦上跑

需要 Python 3.10 以上，**不用安裝任何套件**（只用標準函式庫）。

```bash
py run.py --backfill-days 40
```

第一次會回補 40 個交易日，約 10 分鐘（證交所會封鎖太頻繁的請求，所以每次請求間隔 3.5 秒）。
之後每天跑 `py run.py` 即可，它會自動補抓最近 7 個交易日缺的部分。跑完打開 `docs/index.html`。

其他指令：

```bash
py run.py --skip-update
```

```bash
py -m unittest discover -s tests
```

> **Windows 注意**：如果用的是 MSYS2 / Git Bash 內附的 Python，可能缺 CA 憑證而出現 `CERTIFICATE_VERIFY_FAILED`。
> 請改用 python.org 版本（`py` 指令），或 `pip install certifi`。

## 用 GitHub Actions 每天自動更新

1. 在 GitHub 建一個新 repo，把這個資料夾推上去（`data/` 已經有回補好的資料，可以一起推）。
2. 到 repo 的 **Settings → Pages**，Source 選 **Deploy from a branch**，Branch 選 `main`、資料夾選 `/docs`。
   之後網址會是 `https://<你的帳號>.github.io/<repo 名稱>/`。
   - 免費帳號只有 **public repo** 能開 Pages。private repo 也能自動更新，只是要 `git pull` 後在本機開 `docs/index.html`。
3. 到 **Actions** 分頁，選「更新台股資料」→ **Run workflow** 先手動跑一次確認沒問題。
   如果推上去時沒有帶 `data/`，這一次把 `backfill_days` 填 `40`。
   手動執行時，執行結果頁的摘要會列出每個資料來源的連線檢查（也可以在本機跑 `py -m stock_agent.check`）。
4. 之後會自動執行（台灣時間）：
   - 週一～五 17:30：收盤行情、三大法人
   - 週一～五 22:30：融資融券、補抓漏掉的部分
   - 週六 10:00：集保股權分散表

GitHub 的排程常會延遲 10～60 分鐘。若推送失敗，檢查 **Settings → Actions → General → Workflow permissions** 是否允許寫入。

## 訊號回測

回測涵蓋 17 個快速篩選條件（籌碼 6、基本面 4、技術面 7），以及成交量分布的 3 種 B 訊號。需要一年的每日資料，以及兩年的月營收與每月估值
（營收創新高、本益比低檔要往前比 12 個月）。第一次要回補（約 1 小時，資料會多約 35 MB）：

```bash
py run.py --backfill-days 260 --history-months 25
```

之後每次產生儀表板都會自動重算，也可以在終端機直接看文字版結果：

```bash
py -m stock_agent.backtest
```

計算方式（避免用到當時還不知道的資料）：

- 法人、融資資料收盤後才公布，訊號日的**隔天收盤**進場；月營收在次月 10 日前公布完，**11 日後第一個交易日**收盤進場；
  高殖利率每月第一個交易日檢查（用當天的本益比、殖利率），隔天收盤進場。
- 報酬用每天的漲跌還原計算（含配息）：除權息當天交易所只標「X」，改用證交所、櫃買中心
  「除權除息計算結果表」的參考價算出當天真正的漲跌；不計手續費、證交稅與滑價。
- 每日型訊號只在「條件剛成立」那天算一次，同一段連買不會重複計入。
- 「超額平均」＝訊號股票報酬 − 同一天進場的全部股票平均報酬，再取平均。
- 「超額中位數」「贏過一半股票」是和同一天的「中位數股票」比較：隨機選股大約是 0% 和 50%。
- 表格最上面有四列對照組：隨機選股（全部）、隨機選股（5 日均量 ≥ 300 張）、隨機選股（20 日平均成交值 ≥ 1 億）、
  0050 每天定期定額。成交量大的股票本身表現較好，訊號要贏過「均量 ≥ 300 張」那一列才代表訊號本身有用
  （成交量分布的訊號只看成交值 ≥ 1 億的股票，要和那一列比）；0050 那一列則回答「與其選股，不如直接買大盤？」。
- 成交量分布另有一張表：照個股圖上的 B 進場、S 出場（都是訊號隔天收盤），每筆持有天數不同，
  所以和「同一個進場日到同一個出場日」的中位數股票比較。
- 月營收歷史來自公開資訊觀測站舊版網站的每月彙總頁；每月估值快照來自證交所、櫃買的「依日期查詢本益比」。
- 大戶加碼（集保）與內部人申報沒有官方歷史資料可回補，只能從開始執行後逐週／逐日累積，樣本夠了才會顯示。
- 技術面訊號要先累積股價：均線、相對強弱要 60 天，52 週新高／新低至少要半年，成交量分布要 120 天，
  所以只有回測期間後段的樣本。
- 報酬分布右偏（少數股票漲好幾倍），平均值容易被拉高，請優先看「超額中位數」和「贏過一半股票」。

回測條件寫在 `stock_agent/backtest.py`（`SIGNALS` 與 `daily_events` 等函式），儀表板的快速篩選寫在
`templates/dashboard.html` 的 `PRESETS`；改門檻時兩邊要一起改。成交量分布的清單與買賣點都由
`stock_agent/volume_profile.py` 算好再嵌進儀表板，門檻只要改那一個檔案（說明文字在 `PRESETS` 與 `SIGNALS`）。

> 只有一年的資料，結果深受這段行情影響（例如大多頭時幾乎什麼都漲）。同一天進場的股票走勢高度相關，
> 實際的不確定性比樣本數看起來大。這是統計整理，不是投資建議。

## 成交量分布（Volume Profile）

每個價位成交了多少量。量大的價位代表很多人的成本在那裡，股價回到那裡時容易遇到支撐或賣壓。

- **只有每日資料**：沒有盤中逐筆，所以每天的量整筆放在當天均價（成交值 ÷ 成交量）上；價格用還原股價，
  除權息前後的量才會落在同一個價位。
- **格子**：價格取對數後每 1% 一格。**POC** 是成交量最多的那一格；**價值區**從 POC 往上下擴張，
  每次加入量比較多的一側，直到涵蓋 70% 的成交量（下緣 VAL、上緣 VAH）。
- **不偷看未來**：每天的價值區只用「前 120 個交易日、不含當天」的成交量，個股圖上的灰帶就是每天當時的價值區。
- **只看量大的股票**：20 日平均成交值 ≥ 1 億元才分析，量太小時少數幾筆大單就能堆出假的高量區。

個股圖上的 B／S 依下面的規則自動標註；同一檔同時最多一筆部位，出現 S 之前不會再有 B：

| 種類 | B（買進） | S（賣出） |
|---|---|---|
| 區間低接 | 箱型整理中（同「區間整理」清單的條件），收盤從上方跌到價值區下緣 1% 以內的那天（股價早已待在下緣、或停損後又回到下緣都不算，要先離開再跌回來） | 漲到價值區上緣；跌破下緣 5%；或持有滿 60 日 |
| 跌深反彈 | 距 120 日高點跌 ≥ 20%、POC 在 10% 以上、價值區下緣在 5% 以上，收盤創 10 日新高且離 20 日低點 ≥ 5% | 漲到價值區下緣（套牢區開始的地方）；跌破 20 日低點 3%；或持有滿 60 日 |
| 整理突破 | 60 日高低差 ≤ 25%，收盤站上 60 日高點與價值區上緣、成交量 ≥ 前 20 日均量 1.5 倍、上方套牢量 ≤ 15% | 跌回價值區（突破失敗）；或從進場後最高收盤回落 10% |

目標價、停損價都在 B 那天就決定，之後不會跟著價值區移動。整理突破的報酬分布很偏：多數很快跌回價值區小賠出場，
少數突破後大漲，所以中位數是負的、平均是正的，看結果時兩個都要看。

## 限制與風險

- **資料會延遲或缺漏**：官方公布時間不固定，頁面上方會標示每種資料的日期，比資料日期舊的會以黃色提示。
- **端點可能改版**：證交所、櫃買中心改網站時，抓取可能失敗；失敗會寫進 `data/state.json` 並顯示在儀表板警告區，其他資料照常更新。
- **GitHub 的機房在海外**：若證交所網站封鎖或限制海外 IP，上市三大法人（只有網站端點）可能抓不到；其他資料會改用 OpenAPI 備援。這種情況可改在自己電腦上跑。
- **集保要累積兩週**才有「週變化」；內部人申報從開始執行後逐日累積。
- **repo 會慢慢變大**：每個交易日約 130 KB 資料，加上每次更新重新產生的 `docs/index.html`（約 2.2 MB、
  壓縮後約 0.75 MB；成交量分布圖的資料讓它比原本大了約五成）。沒有新資料時程式不會改動任何檔案，所以不會產生空的提交。
- 指標只是整理公開資料，**不是投資建議**，也不保證任何報酬。
